# 政企 + RAG 面试求职案例集

> 整理自 JavaGuide 星球答疑，涵盖政企数字化、银行金融科技、传统行业 Java 开发者的求职转型案例，共 11 个案例。
>
> **文档结构**：每个案例统一为「提问 → 简历（如有）→ 回答与建议」格式，末尾附个性化咨询方法指南。

## 案例1：中小型央企后端 6 年（3 年开发 + 3 年交付负责人），面临被裁

### 提问

> 你好，我毕业即加入一个中小型央企，前面 2-3 年做了后端，参加过 3 个项目，在政府类项目使用过 SpringBoot、SpringCloud、ES，但是我当时没有对源码的理解，说白了类似 CRUD。后面 3 年做项目交付负责人进行项目交付，对技术方面积累基本没有。部门业务调整即将被裁，目前已经是金三银四的时期，我该如何准备呢？

### 回答与建议

**1. 政府类项目经验是优势**

央国企项目技术含量不高是常态，但技术栈主流（SpringBoot + ES）已属不错。政府类项目的 CRUD 和互联网 CRUD 不是一回事——权限模型、审批流、数据上报、对接接口、信创适配、等保要求，都是硬门槛。

**2. 项目包装思路**

把项目中解决的具体问题列出来：
- 多级审批怎么设计的？
- 对接时遇到的问题怎么排查的？
- 引入工作流引擎、缓存等技术亮点
- 结合政企场景的 AI 亮点（如政务政策智能问答知识库）

**3. 交付负责人经历的定位**

3 年交付经历积累了沟通协调、需求管理、风险控制等软技能，在项目经理、技术负责人岗位上很重要。面试纯技术岗位可弱化，否则应突出。

**4. 求职方向**

政企数字化市场需要"懂政府项目的人"：智慧城市、政务云、园区管理、物业科技等方向，更看重是否有类似项目经验。

## 案例2：银行 Java 开发 4 年 + 1 年断档期，武汉求职

### 提问

> Guide 哥，我在广东某家银行作为后端 Java 开发工作了 4 年，银行的工作偏向业务，私下里也学了不少慕课的课，但是感觉是只会做，不会说，技术大部分能用就行，很少会去钻研底层。然后有一年断档期，现在打算在武汉找工作，但是害怕这边的面试问的很深，我应该如何准备现在的面试和如何提升自己，看过很多架构课感觉收获一般。谢谢。

### 回答与建议

**1. 业务经验就是优势**

银行项目偏业务（流程、审批、对账、报表、风控、权限、审计），这些是优势，不是只有高并发才算亮点。AI 时代，懂业务、有特定场景经验的人更有竞争力。

**2. 停止刷架构课**

架构课看着爽，但落不到简历上。建议拿出一个银行项目，画三张图：
- **业务流程图**：谁发起、经过哪些系统、落哪些表
- **系统调用图**：各系统间调用关系
- **关键表关系图**：核心表结构与关联

选取授信、支付、对账、客户信息、报表、审批流等模块，讲清楚：失败怎么补偿？有没有幂等？有没有人工复核？

**3. 技术准备策略**

不要按应届生方式从 Java 基础一路背。4 年经验，面试官更希望听到你怎么处理业务里的麻烦事：事务、慢 SQL、索引、批量任务、定时调度、接口超时、重复提交、权限控制、日志审计、数据修复。

**4. 表达能力训练**

每个项目准备 10 个问题，每题录音讲 2 分钟：
1. 项目做什么？
2. 你负责什么？
3. 最复杂的流程？
4. 最麻烦的 bug？
5. 一次慢 SQL 排查？
6. 一次接口异常处理？
7. 一个表设计？
8. 一个事务边界？
9. 一个权限点？
10. 一个你后来想优化的地方？

讲不下去的地方，就是你要补的技术点。

**5. 断档期怎么说**

别说太复杂："前一阶段离职后处理个人事务，同时做技术复盘和求职准备，现在已经确定在武汉长期发展。"

**6. 求职方向**

不只盯互联网后端，金融科技、银行外包、政企数字化、国企信息化、传统软件公司都可以投。"懂金融业务、懂银行系统约束"就是优势。

## 案例3：普本 27 岁，传统政企 3 年 Java，低薪想跳槽 + 考公

### 提问

> Guide 哥，你好。我先简单介绍一下我的情况：22 年毕业，普本，27 岁，算是有四年的 Java 开发经验，传统政企行业，成都低薪底层牛马。
>
> 有过两段工作经历，第一段时间不长，完全没什么用还浪费了应届生的身份。现在这家公司待了 3 年了，从 24 年公司架构调整了之后，公司各种砍福利，整花活恶心人，就想跑路了。当时想着工作时间不长不好找，又希望能拿到一个裁员名额，就先呆着，这一呆就好似温水煮青蛙。回顾了一下这三年，大大小小的项目也做了那么多，但是沉淀不了什么东西出来，整体就偏业务，公司的技术架构也是垃圾得很。我的工作也就是写些业务接口，做业务系统，当然都是低薪底层牛马了，就是什么都干了：前端、后端、文档、对接、数据处理、运维，就差产品和测试了。
>
> 25 年 AI 大爆发，各种铺天盖地的推送程序员要完了，进一步给自己加了一层思想负担。自己已经没有拼劲儿了，完全就是否定自己了，也不敢裸辞。因为自己本身薪资低嘛，加上 AI 发展这么迅猛，就不知道该怎么办了。想跳槽呢，感觉自己没资本；继续待下去呢，也不知道能待多久。家里边倒是希望我能考公，去年也尝试考了下，一百零几，上岸还差得多……
>
> 越发觉得，我这种普本 + 传统 Java 牛马没救了。感觉只剩下焦虑了，被生活磨得没有脾气了。

### 回答与建议

**1. 停掉 AI 论文和生图原理的学习**

扩散模型、U-Net、采样器、论文解读——这些是做算法、做模型、做 AIGC 研究的人看的。转 AI 应用开发和算法岗差别很大，AI 应用开发更像是后端开发的延伸：

- 调用大模型 API
- 把模型接到业务系统里
- 做 RAG、工具调用
- 权限、限流、日志、成本控制、失败重试、灰度、监控

**2. AI 应用开发只需知道这个程度即可上手**

| 概念 | 理解程度 |
|------|----------|
| Token | 怎么计费的 |
| 上下文窗口 | 为什么会爆 |
| Embedding | 把文本变成向量 |
| RAG | 先检索再把材料塞给大模型 |
| Agent | 让模型决定调哪个工具 |

**3. 政企经验的迁移价值**

政企项目虽技术架构可能差，但做过业务系统、跨系统对接、数据处理、运维和线上问题排查——这些恰好能迁移到 AI 应用：企业内部知识库、智能客服、工单助手、合同问答等，本质都要接原来的业务系统、权限体系和数据源。

**4. 做一个 AI 应用项目**

选一个小场景（如企业内部知识库 RAG、模拟面试系统），完成完整链路：
- PDF/Markdown 文档解析 → 切分 → 向量入库 → 语义检索 → 重排 → Prompt 拼接 → 流式输出
- 补上：登录鉴权、接口限流、调用日志、失败重试、Token 统计

**5. 关于考公**

如果对公务员生活不抵触，可以定一个周期认真准备。如果只是因为害怕跳槽才想考，最后技术没准备好、考试也没准备好。

**6. 一个月行动计划**

1. 写出简历初版
2. 从过去项目里挖两个能讲的业务/技术问题
3. 用一个月补一个 AI 应用项目
4. 一个月后开始投，边投边复盘

## 案例4：二本计科，小厂 1.5 年 + 考公失败 + 外包 offer 犹豫

### 提问

> Guide 哥你好，我想向你咨询一些求职建议。
>
> **背景**：我是 21 年二本计科毕业，然后在小厂当程序员大约 1 年半不到 2 年，22 年底选择了辞职考公，很可惜就是没考上。现在我来到了广州。
>
> **目前主要问题**：7 月 1 号开始投简历，做好找一两个月的准备，但是有一个外包面试突然过了，犹豫要不要去。这是个联通的外包（也可以说是甲方的内包），薪资 11K 左右，一年一签的。3 号也就是上周五线上面试，今天 HR 说过了。
>
> **个人担忧**：
> ① 我个人不太想去，或者说不太敢去。一方面毕竟是外包，也说了一年一签怕不稳定；另一方面，我清楚自己的能力情况，项目没有摸得很熟，八股文更是相当于没有，本身也是打算边面试边练级的，所以这个面试过得很突然。更重要的，线上面试面试官也没问我什么项目相关的（可能就问了一个 RAG 的流程，然后他问我 Linux 和 Docker 一些具体用法，但是他又说我没用过问不了，就这么自顾自说完了，最后问我工作中遇到过什么印象深刻的难题，我准备不充分也没说啥，反正感觉聊了会儿天就结束了）。对比之下，还有另外几场问得比较细的就没有回音，更让我感觉这个外包是不是很急，或者有其他坑。
> ② 虽然不太想去，但是结合自身情况，又怕错过这次之后找不到了，怕自己白忙活一个月之后连和这一份工作类似的都没找到——我清楚自己实力不济，不是谦虚，况且我也好几年没工作没收入了。
> ③ 进入到公司之后（不一定是这家），如何快速融入其中，或者说通过试用期，我很担忧领导一上来就让我自己搭一个项目，瞬间露馅，试用期都过不了。
> ④ 经过第一周的外包疯狂海投之后，Boss 上几乎没有主动找我聊天的了，我要自己投递了，我打算从 8-9K 的岗位开始投，目标 12-13K。还是想问问 Guide 哥有什么意见，后续复习方向？
>
> 最后附上简历，有参照你之前的文章改过的。

### 回答与建议

**1. 接不接外包？**

外包确实有点坑，但现实是空窗较久 + 手里只有一个 offer。在接之前先问清楚：
- 合同主体、社保公积金、试用期工资、工作地点
- 派驻团队、加班情况、项目周期
- **最关键**：这个岗位进去后第一个月主要做什么？有没有现成项目和带我的同事？

如果信息清楚、工资发放正常、手里无其他 offer，可以先接。

**2. 一年一签不用过度恐惧**

按《劳动合同法》第十四条，固定期限劳动合同合法。外包真正的不稳定来自：项目预算、甲方换供应商、派驻团队边缘化、没人带。

**3. 面试太水要警惕**

可能是项目缺人只要能到场干活就行，也可能是业务侧不懂技术只看关键词匹配。这种公司通常稳定性差。

**4. 入职后如何快速站稳**

- 第一周：跑通本地环境、登录链路、一个查询接口、一个新增/修改接口，摸清配置、表结构、日志、部署入口
- 每天主动同步：今天看了什么、卡在哪里、明天准备做什么
- 领导让从零搭项目时：先问有没有公司脚手架、相邻项目、数据库规范、鉴权规范、日志规范、部署规范

**5. 简历问题**

AI 部分写得太满——Spring AI、RAG、Agentic Workflows、ReAct、Function Calling、Prompt Injection 防御全摆上去，面试官稍微懂一点就会顺着问细节。简历上每句话都要能讲 3 分钟。

**6. 投递策略**

| 薪资范围 | 定位 |
|----------|------|
| 8-10K | 保底池 |
| 10-13K | 主投池 |
| 13-15K | 试探池 |

每天优先投"1-3 年或 2-4 年、Spring Boot、MySQL、Redis、ToB 业务系统、AI 应用或 RAG 加分"的岗位。

**7. 打招呼语模板**

> "你好，我有 1 年半 Java 后端开发经验，近两年做过项目制开发，熟悉 Spring Boot、MySQL、Redis，最近做过 Spring AI + pgvector 的 RAG 面试系统，广州可尽快到岗，方便的话麻烦看下我的简历。"

重点是"能尽快到岗"和"项目关键词匹配"。

**8. 一个月复习分配**

- 项目复盘：占一半时间
- Java 高频 + MySQL + Redis + Spring Boot：占另一半
- RAG 链路要能讲：文档解析 → 切分 → Embedding 模型 → pgvector 索引 → 召回和重排 → 上下文拼接 → 幻觉兜底

## 案例5：双非考研失败，外卖项目 + Agent 项目约不到面试

### 提问

> Guide 哥你好，我想向你请教一些建议和方向。我的情况是 25 届双非本，考研一战下岸后找了个地方性国企干 ERP 系统管理维护，当时他们在数字化转型，就各种系统包括 OA 什么的都需要管理，偶尔还有内部系统二次开发什么的很杂，就辞职考研二战了。现在也是下岸后找工作。
>
> 目前我敲完外卖，掌握到 SpringBoot 的程度，看了一下 Agent 开发，写了一个小 demo 很浅基于 LangChain4j 的，但是挺全的 RAG、工具调用、MCP 什么的都用到了，对 Agent 有了一点理解后就开始海投简历，Java 开发、Agent 应用开发什么的都在投。
>
> 我技术栈还是不太成熟，简历包装的外卖和一个 Agent 项目，但是基本约不到面试，现在感到很迷茫和焦虑，求 Guide 哥给孩子指点迷津叭。

### 回答与建议

**1. 核心问题：简历不过关**

约不到面试说明简历在筛选阶段就被刷了。外卖项目是重灾区，太多人写，面试官一看就知道是学习项目。

**2. 两个可用的素材**

- 国企 ERP 系统管理和二次开发的经历 → 包装成正式工作经历
- 基于 LangChain4j 的 Agent demo → 作为项目经历

**3. 外卖项目处理**

不想放弃外卖项目的话，参考星球项目资料合集进行完善包装，不能用培训机构那套话术。

**4. Agent 项目深度不够**

只是跑通 LangChain4j 示例太浅，需要加业务场景：
- 做一个基于 RAG 的企业知识库问答系统
- 接入真实文档
- 加上工具调用和多轮对话
- 包装成完整产品而非 demo

**5. 投递策略**

- 关键词搜索："Agent 开发""RAG""AI 应用"
- 重点投"Java 后端 + AI 方向"岗位（要求 Spring Boot + AI 应用开发能力）
- 不只投中大厂，企业服务中小公司、AI 创业公司也在招这类人

## 案例6：政务系统 5 年，技术基础，简历石沉大海

### 提问

> Guide 哥，我之前在一家做政务系统的公司上班快五年了，项目不少，但是技术都比较基础。对于 Redis 或者 MQ 这些主流中间件的使用也比较基础，比如缓存一下系统配置这些，因为政务系统的并发量都不高。平时的开发工作主要也是增删查改，业务逻辑更多是要满足政策要求。但是现在因为个人原因，我希望能换一个更稳定的工作。投了一些简历，回复的一般都是外包公司。有些心仪的岗位像银行开发看招聘要求我都有涉及，但是简历却石沉大海。

### 回答与建议

**1. 问题诊断**

五年政务系统经验在技术层面和市场需求不匹配。政务系统虽并发量低，但稳定性、安全性、数据准确性要求极高——这些都是可重新包装的能力维度。

**2. 简历包装思路**

| 原描述 | 优化后 |
|--------|--------|
| 使用 Redis 缓存系统配置 | 设计并落地配置中心缓存方案，实现配置变更秒级同步，支撑日均 10 万次读取 |
| 根据政策要求开发业务模块 | 深入理解行业监管政策，将业务规则抽象为可配置化规则引擎，支持运营人员零代码调整业务逻辑 |

**核心原则**：不是编数据，是把工作成果用技术语言重新表达。

**3. 可挖掘的亮点方向**

数据治理、异构系统对接、政策规则引擎——这些在面试金融、医疗、政务数字化的公司时比较适配。

**4. 职业发展方向（追求稳定）**

- **银行科技子公司**：建行金融科技、工行软开等
- **央国企信息化部门**
- **政务数字化上市公司**

这些地方的稳定性来自业务属性，面试通常会考察：稳定性、对体制文化的理解、技术能不能落地。

## 案例7：金融科技 5 年 Java，想冲击中大厂 ⭐（含完整简历范例）

### 提问

> Guide 哥好，我是一个在金融科技公司里 5 年 Java 开发经验的牛马，想请教你对我的简历进行指导一下。
>
> **个人背景**：2021 年双非本科毕业，校招进入某国企金融科技公司，负责集团内部金融子公司的业务系统的信息化建设。工作虽然稳定，也干过不少 dirty work，但是晋升通道极窄。今年下定决心要跳出舒适圈，想冲击中大厂给自己简历镀金。个人技术中规中矩，历经 5 年，有时候遇到很多不懂/半懂的技术都能凭借个人经验对理论快速理解，就是实战经验少了些。
>
> **简历背景**：简历内容是基于市场招聘要求 + AI 美化后的版本，专业技能基本都有实际使用过但可能不深入。另外增加了 AI 智能面试平台，个人打算包装为公司内部 OA 跳转的系统，其余的都是真实项目，基本上没有太多高大上的技术，实际开发以 CRUD 为主。

>
> 最近我认真思考过自己的职业规划，希望利用未来几个月时间系统补齐技术栈，准备面试并尝试跳槽，目标是在武汉找到一份月薪 1 万元左右的 Java 开发岗位。
>
> 我比较困惑的是：
> 1. 以我目前的背景和技术水平，在武汉市场是否具备拿到 1 万元以上薪资的竞争力？
> 2. 未来几个月应该优先补哪些技术栈，才能让投入产出比最高？
> 3. 对于长期做传统行业项目的人来说，跳槽时最容易被面试官质疑哪些问题？
> 4. 目前继续深耕 Java 后端是否还有竞争力，还是应该考虑转向其他方向？
> 5. 如果是你站在我的位置，会如何规划未来 1 年的成长路线？

### 回答与建议

**1. 目标可达，但不能直接投**

武汉 Java 3~5 年岗位税前 10K~15K 的 JD 很多，25 岁 4 年经验目标 1W+ 不难。但当前经历听起来像"运维 + 维护 + 改需求"，面试官会担心你只是在老系统修修补补，没独立做过模块、排查过复杂问题、优化过性能。

**2. 把"维护系统"转成"解决业务问题"**

供应链系统里一定有订单、库存、调拨、对账、报表、审批流、定时任务。要改述为：
- 某个报表很慢 → 你怎么定位 SQL？
- 某个库存数据不一致 → 你怎么排查？
- 某个流程经常出错 → 你怎么改造？
- Oracle 查询迁到 MySQL → 遇到什么兼容问题？

**3. AI 时代业务经验更值钱**

AI 能写代码但不懂烟草供应链里的调拨、库存、对账、审批、报表口径。利用这几年业务经验，优先投供应链、物流、仓储、制造、政企数字化、ERP、报表平台等行业公司，别只盯着纯互联网岗位。

**4. 优先补哪些技术栈**

| 优先级 | 内容 | 程度要求 |
|--------|------|----------|
| 必补 | Java 基础、集合、并发 | 熟练掌握 |
| 必补 | MySQL | 看索引、搞清事务和锁、分析慢 SQL |
| 必补 | Redis | 常见数据结构、缓存穿透/击穿/雪崩、分布式锁 |
| 必补 | Spring Boot | 能从零搭项目跑通 |
| 够用就行 | Docker | 会部署自己的项目和中间件 |

**5. 项目不要新造，基于现有经历改造**

挑一个熟的模块，补上：接口设计、数据库设计、缓存优化、慢 SQL 优化、异常兜底、日志和监控。哪怕部分内容是业余复盘补出来的，也比空背八股强。

**6. Java 后端肯定还能做**

现在积累得太窄，不是 Java 方向没前途。换方向会让之前的工作经验更难解释。先用 6 个月把 Java 后端求职能力补起来。

**7. 3+6+3 规划**

- **第 1~3 个月**：写简历初版，集中补 Java 基础/MySQL/Redis/Spring Boot，重写优化项目经历
- **第 2 个月起**：围绕简历准备面试题和项目追问，挑模块做小优化改造
- **第 3 个月起**：直接开始投，拿面试反馈继续补短板
- **第 6~12 个月**：成功跳到更有开发强度的岗位后，再补微服务、消息队列、Docker 深入

> 最该避免的是继续拖——再学半年但简历没改、项目没复盘、一次面试都没投，半年后还是慌。

## 总结：政企/传统行业 Java 开发者的共性策略

### 通用建议

1. **停止无效学习**：架构课、AI 论文、底层源码——在项目都讲不清楚的时候性价比极低
2. **业务经验是核心优势**：政企、银行、政务、供应链、房地产项目的业务复杂度本身就是护城河，AI 时代更是如此
3. **项目必须包装润色**：用"技术 + 场景 + 效果"（B-T-A-R 模型）重新表达工作成果，不是编数据，是用技术语言翻译
4. **简历上每句话都能讲 3 分钟**：面试官顺着简历问是基本操作，简历写上去的技术点必须彻底吃透
5. **AI 应用开发不是算法岗**：只需知道 Token、上下文窗口、Embedding、RAG、Agent 的工程化层面，不需要啃模型原理
6. **做一个完整的 AI 应用项目**：选小场景，跑通完整链路（文档解析 → 向量入库 → 检索 → Prompt 拼接 → 流式输出），补上工程化能力（鉴权、限流、日志、重试、监控）
7. **边准备边投，不要等"学完"再行动**：市场反馈会告诉你到底差在哪
8. **表达训练用笨办法**：每个项目准备 10 个问题，每题录音讲 2 分钟，讲不下去的地方就是短板

### 求职方向拓展

不只盯互联网后端，以下方向对政企/传统行业背景的开发者更友好：
- 金融科技、银行科技子公司
- 政企数字化、政务云
- 国企信息化部门
- 智慧城市、园区管理、物业科技
- 供应链、物流、仓储、制造、ERP
- AI 应用开发（Java 后端 + RAG/Agent）
- 传统软件公司

## 案例10：招银 3 年 + 空窗 1 年，前端转后端，既不会后端又不会 AI

### 提问

> Guide 哥你好，我是双非本科毕业，在招银工作了三年后去年 6 月因为公司没续约没干了。本来想马上准备找工作，但因为贪玩一直断断续续拖到了现在。最近想重新搞起来，想问下该怎么准备好。
>
> 我自己后端基础其实不太扎实，当时是面的前端进去转岗到后端的。在公司三年感觉也基本都是面向银行业务需求开发啥的，好像没用上什么高深的技术。去年还没离职那会儿 AI 还没现在这么厉害，当时在公司也就用来辅助找 bug。现在我感觉既不会后端又不会 AI，有点迷茫了。而且空窗一年了，还不知道编个什么理由好。

### 回答与建议

**1. 空窗一年要先正视，再解释**

空窗一年还断断续续准备，确实不太应该。你得利用后面的时间，真的做出来点东西，尤其是要优化改进过往的项目经历，不然面试中确实不太好说。

空窗期解释："去年离职后休整了一段时间，也处理了一些个人事务，后面开始系统补后端基础，并做了一个 AI 应用项目练手。"

**2. 招银三年经历有认可度**

银行业务开发听起来技术含量低，但里面有流程、权限、审批、数据一致性、老系统维护、问题排查——这些都能讲。要把以前做过的需求重新拆一遍，找出 2~3 个能讲的业务链路。如果确实缺少技术亮点，那就自己包装一些合理的，毕竟现在很多银行的项目技术栈还是比较主流的，只要吃透搞懂，面试中就能说清楚。

**3. AI 应用开发路线更适合**

后端背景走 AI 应用开发更合适。先把 LLM 调用、Prompt、RAG、向量库、流式输出这些跑通，做一个小而完整的项目（知识库问答、简历解析、模拟面试都可以）。模型多高级先放一边，你要能讲清楚：数据怎么进来、怎么检索、怎么防止乱答、接口怎么保证稳定。

**4. 时间安排别太散，优先级要清楚**

最大的风险排序：**后端基础虚 > 简历没货 > 面试状态断太久 > AI 缺失**。AI 反而排在后面。

- 先写简历，哪怕很烂也先写出来，它会逼你看到短板
- 一边补 Java 后端基础，一边把过去三年项目复盘出来
- 再用 AI 项目补一个新亮点
- 现金流紧的话，先把目标放到能接住你的中小厂和金融科技外包/自研岗位，别一上来就幻想一步到位

**5. 每天都要有可见产出**

- 一段项目复盘
- 一组八股自测
- 一次投递
- 一次模拟面试

> 靠焦虑想不出路，靠产出才行。

## 案例11：双非本 + 上海 211 硕，2028 年毕业，Java 后端如何进大厂

### 提问

> Guide，安徽双非本科，上海 211 硕，本硕专业都是计算机专业，Java 后端，有没有机会进大厂呢？有什么建议吗？2028 年毕业。学习后端有什么建议吗？

### 回答与建议

肯定有机会的。上海 211 硕，学历这块已经达标了，能过绝大部分公司的简历门槛。

**1. 实习和项目都不能少，尤其是实习**

现在的大厂面试太卷了，只靠学历和八股很难稳。你这个阶段最重要的事情，就是尽早积累实习经验，最好是中大厂、准大厂或者业务和技术都还不错的中厂实习。

**2. 校招时间线规划**

2028 年毕业，时间还比较充足，但也不要懈怠，尽早开始投递实习：
- 明年的 3 到 5 月：暑期实习重点留意
- 6 到 8 月：看提前批
- 9 到 10 月：打正式秋招
- 2028 年 3 到 5 月：春招兜底

**3. 导师不让实习怎么办**

如果导师不允许出去实习，也要尽力争取。这个对你后续校招面试大厂非常重要，不是可有可无。可以提前跟导师沟通，把课题进度、组内任务、实习时间说清楚，争取暑期两三个月，或者争取日常实习每周固定几天。真拿到不错的实习 offer 之后，再去沟通，成功率往往比空口说想实习高。

**4. Java 后端技术准备**

先把 Java 基础、集合、并发、JVM、MySQL、Redis、计算机基础这些打扎实。微服务、分布式、源码根据情况准备，这些这两年问的也没有那么多了。不过，高并发相关的依然是香饽饽，需要重点准备。

**5. 项目准备**

项目准备两个就行，但要吃透：
- 一个偏业务系统的项目：能讲清楚用户、订单、权限、库存、支付、审批这类流程
- 一个偏技术亮点的项目：比如缓存、消息队列、搜索、文件存储、AI 应用、性能优化

**6. 算法要早点刷**

大厂后端校招目前还绕不开算法。先刷数组、链表、哈希、栈队列、二叉树、二分、动态规划基础题，先把手感练出来。

**7. AI 作为加分项，别把 Java 后端主线丢了**

如果感兴趣，可以将一个项目定位 Java 后端 + AI，比如模拟面试、智能客服、代码审查助手。面试时能讲清楚后端工程、数据流转、权限和稳定性，比只会调模型接口强更有说服力。

**8. 投递策略**

不要只盯最头部的几家。大厂、准大厂、银行金融科技、车企数字化、云厂商、ToB 软件公司都投。第一段实习能进一个不错的平台就很好，别非要第一步就拿最顶级 offer。先拿到一段能写进简历、能被追问的开发实习，然后再慢慢跳更好的。
