简单描述自己做了什么，解决了什么问题，带来了什么实质性的改善。突出自己的能力，不要过于平淡的叙述。

下面是原项目常见描述优化版，以单体架构为例介绍（**一定不要原封不动的 copy，也不用写这么多条，适当删减，适当润色一下，结合自己的实际情况来写**）：

1. 开发和维护用户登录、权限校验、课程管理和媒体资源管理模块。

11. 基于 JUnit + Mockito 编写测试代码，通过 JaCoCo 生成单测覆盖率报告。
12. 基于 AOP + 注解统一日志记录，并结合 Spring 框架实现全局异常处理。
13. 通过 Freemarker 模板引擎实现课程页面静态化并保存在 Nginx，提高响应速度，减轻服务器压力。

### 1.5 可优化的方向

下面是我总结的一些可添加/修改的点（可形成差异化的描述）：

1. **FFmpeg 异步处理**：FFmpeg 处理 MP4 视频可引入队列实现异步，例如 Redis 5.0 中增加的 Stream 类型。如果对实时性要求不高的话，可以基于定时任务来做，例如 Spring Task、XXL-JOB。

2. **CompletableFuture 并行加载**：基于 CompletableFuture 并行加载网站首页的课程分类、热门课程等数据。具体思路可以参考星球的分享：<https://t.zsxq.com/oEXEh>

3. **课程排行榜**：维护一个课程/视频排行榜（根据课程/视频发布时间、点赞数、学习人数等数据来计算热度），可以基于 Redis 的 Sorted Set（有序集合）来维护排行榜，使用 SpringTask/XXL-JOB 实现排行榜的定时维护更新。尽量支持当天、最近七天、最近一个月多个维度的热度分析。

4. **付费课程 + 营销功能**：如果存在付费课程的话，可以引入优惠券、拼团购买等功能，这些属于常见的营销手段。可以找一些优惠券项目看看，模仿着整合一两条核心职责到该项目中去。

5. **EasyExcel 导入导出**：课程管理模块可以基于 EasyExcel 实现课程信息的导入导出功能，配合线程池提高导入导出效率，导入记得批量写入。

6. **生产问题排查经验**：引入一些生产问题的解决经验到个人职责介绍中，可以参考之前分享过的线上常见问题案例：<https://t.zsxq.com/0dobVUIx7>

7. **AI 能力整合**：对接 AI 大模型 API（比如 ChatGPT、通义大模型）实现一些有亮点的功能，例如视频内容总结、一对一问答。

### 3.2 认证授权

认证授权是开发难度相对较大的一个功能，对于在校学生来说。

认证授权可以基于下面三个框架来做：

| 框架 | 特点 |
|------|------|
| **Sa-Token** | 轻量级 Java 权限认证框架，支持认证授权、单点登录、踢人下线、自动续签等功能。开箱即用的功能更多，使用也更简单。 |
| **Spring Security** | Spring 官方安全框架，能够用于身份验证、授权、加密和会话管理，是目前使用最广泛的 Java 安全框架。 |
| **Shiro** | Java 安全框架，功能和 Spring Security 类似，但使用起来更简单。 |

一般来说，Spring Security 用的最多，最权威。国人开源的 Sa-Token 易用性更强，也可以使用。个人的话，更推荐 Spring Security，因为 Sa-Token 提供的开箱即用的功能太多，面试反而不太好发挥。

在面试的时候，结合你选择的框架去讲就好了。实际面试中不会问太难，你搞清楚你用的框架的认证授权的逻辑以及认证授权的一些常见概念就可以了，不用太担心。

### 3.3 文件存储

面试的时候，面试官可能会问你视频、图像等文件资源的底层存储是什么以及为什么这样选择。

当你说选择的是开源文件存储系统的话，面试官可能会追问你（这里以 MinIO 为例）：

1. 有没有对比过其他开源文件存储系统？
2. 为什么最后用 MinIO？MinIO 有什么优势？
3. MinIO 的纠删码是什么？有什么用？
4. MinIO 如何实现高可用？如果某个节点出现故障，数据仍能正常访问吗？

文件的底层存储一般可以选择：

- 本地磁盘（不推荐）
- 对象存储服务（比如阿里云 OSS、腾讯云 COS）
- 开源文件存储系统（比如 FastDFS、MinIO、Ceph）

> 我这里是以 MinIO 为例进行说明的，不代表你就必须也按照这个来写。你也可以选择对象存储服务如阿里云 OSS，或者其他开源文件存储系统例如 Ceph。

#### 本地磁盘

不推荐使用本地磁盘作为文件的底层存储，缺点如下：

- **扩展性太差**：不支持存储空间的动态扩展，假如我们的磁盘空间不够用了，你想扩展存储空间会非常麻烦。
- **功能性太弱**：不具备自动备份、数据恢复等功能，需要我们自己开发，增加了开发和维护的难度。
- **可靠性较差**：本地磁盘出现硬件故障的话，可能会导致数据丢失。
- **性能较差**：本地磁盘的读写速度相对较慢，无法满足大规模并发访问的需求，容易导致文件响应变慢，甚至崩溃。

**推荐使用对象存储或者开源文件存储系统来做。**

#### 对象存储服务（OSS）

对象存储服务（Object Storage Service，OSS）是一种海量、安全、低成本、高可靠的云存储服务，适合存放任意类型的文件。容量和处理能力弹性扩展，多种存储类型供选择，全面优化存储成本。

常见的云服务商如阿里云、腾讯云、七牛云、AWS 等都提供了对象存储服务。这里以阿里云 OSS 为例说明。

> 阿里云 OSS Java SDK 参考文档：<https://www.alibabacloud.com/help/zh/object-storage-service/latest/java-introduction>

**面试常见问题：**

1. **项目是如何使用阿里云 OSS 的？**
   直接在项目中使用对应语言的 SDK 即可实现存储空间和文件增删改查，前提是你已经开通了 OSS 服务并且已创建 AccessKey。

2. **为什么要使用 OSS（有什么好处）？**
   - 可靠性强：可提供 99.9999999999%（12 个 9）的数据持久性，99.995% 的数据可用性。
   - 安全性强：支持防盗链配置、基于 SSL/TLS 的 HTTPS 加密传输、文件版本控制、细粒度文件读写权限控制等。
   - 扩展性强：不限制存储空间大小，可以根据所需存储量无限扩展。
   - 成本较低：无需传统硬件的采购、部署和运维，支持按量付费。
   - 接入方便：提供标准的 RESTful API 接口、丰富的 SDK 包、客户端工具、控制台。

3. **Bucket 是什么？**
   在阿里云 OSS 中，Bucket（存储空间）是一个基本容器，用于存储数据对象（即文件）。可以将 Bucket 视为一个高级的"文件夹"，它存储数据并且可以全球访问，依赖于用户配置的权限和策略。

4. **如何加速 OSS 的访问？**
   直接访问 OSS 资源，访问速度会受到 OSS 的下行带宽以及 Bucket 地域的限制。如果通过 CDN 来访问 OSS 资源，带宽上限更高，并且可以将 OSS 的资源缓存至就近的 CDN 节点，通过 CDN 节点进行分发，访问速度更快，且费用更低。

5. **如何防止 OSS 中的文件被盗链？**
   OSS 支持对存储空间（Bucket）设置防盗链，即通过对访问来源设置白名单的机制，避免 OSS 资源被其他人盗用。

6. **阿里云 OSS 支持版本控制吗？**
   支持。版本控制允许用户保存和管理存储在 Bucket 中的每个对象的多个版本，可以访问和恢复任何先前版本的对象。

#### MinIO（开源文件存储系统）

相比较于对象存储来说，开源文件存储系统提供的功能一般要少一些，但其优势在于比较灵活，比较适合中小型项目。

开源文件存储系统一般选择 MinIO 和 FastDFS 的多一些。个人推荐使用基于 Go 语言开发的 MinIO，其功能非常强大，并且这是世界上最快的对象存储，没有之一。

根据 MinIO 官网介绍：

- MinIO 提供高性能、与 S3（全球范围内达到共识的对象存储的协议，由亚马逊 AWS 制定）兼容的对象存储系统，让你自己能够构建自己的云储存服务。
- MinIO 原生支持 Kubernetes，它可用于每个独立的公共云、每个 Kubernetes 发行版、私有云和边缘的对象存储套件。
- MinIO 是软件定义的，不需要购买其他任何硬件，在 GNU AGPL v3 下是 100% 开源的。
- MinIO 使用纠删码、Checksum 来防止硬件错误和静默数据污染。在最高冗余度配置下，即使丢失 1/2 的磁盘也能恢复数据。

> ⚠️ **注意**：MinIO 目前已经不免费商用了，并且价格比较贵。MinIO 官网已经写的非常清楚，你用了开源版 MinIO，就必须得开源自己的源代码，很显然这并不适用于公司。如果你想找到免费商用版本的话，可以选择之前基于 Apache License 2.0 协议的版本，比如 [RELEASE.2021-04-22T15-44-28Z](https://github.com/minio/minio/releases/tag/RELEASE.2021-04-22T15-44-28Z)。

- MinIO 中文官网：<https://www.minio.org.cn/>
- GitHub 地址：<https://github.com/minio/minio>

**面试常见问题：**

1. **有没有对比过其他开源文件存储系统？**
   也考虑过使用 FastDFS，但经过详细对比之后发现 MinIO 具有下面这些优势：

   | 对比维度 | MinIO | FastDFS |
   |----------|-------|---------|
   | 安装部署 | 安装部署简单，开箱即用 | 安装部署较为复杂 |
   | 官方文档 | 有详细的官方文档参考 | 没有官方文档，参考资料少 |
   | 社区活跃度 | 公司项目，社区活跃，更新频繁 | 个人项目，社区不活跃，更新不频繁 |
   | UI 界面 | 自带 UI 界面，开箱即用 | 默认不带 UI 界面 |
   | 性能 | 世界上最快的对象存储，没有之一 | 性能相对较弱 |
   | S3 协议 | 支持 S3 协议，兼容主流云存储服务 | 不支持 S3 协议 |
   | 云原生 | 提供与 Docker、K8s 等深度集成方案 | 云原生支持不友好，需自行改造 |

2. **为什么最后用 MinIO？MinIO 有什么优势？**
   上一个问题的答案已经表明了 MinIO 的优势。

3. **MinIO 的纠删码是什么？有什么用？**
   多副本策略和纠删码（Erasure Code，简称 EC）是存储领域常见的两种数据冗余技术。相比于副本策略，纠删码具有更高的磁盘利用率。

   | 对比维度 | 多副本（3 副本） | 纠删码（n+m） |
   |----------|:------------:|:----------:|
   | 磁盘利用率 | 1/3 | n/(n+m) |
   | 计算开销 | 几乎没有 | 高 |
   | 网络消耗 | 较低 | 较高 |
   | 恢复效率 | 较高 | 较低 |

   分布式 MinIO 使用 Reed-Solomon（简称 RS）纠删码将对象拆分为 n 个数据块和 m 个校验块。默认是拆分成 N/2 数据块和 N/2 奇偶校验块，其中 N 是磁盘数量。这意味着即使丢失集群中一半的节点或硬盘，也仍然可以通过剩余的数据块和奇偶校验块来恢复数据。

   > 扩展阅读：[有趣的纠删码(Erasure code)](https://www.jianshu.com/p/4ebf2dfd39bf)、[纠删码 Erasure Coding（分布式存储系统）](https://zhuanlan.zhihu.com/p/23172828)

4. **MinIO 如何实现高可用？如果某个节点出现故障，数据仍能正常访问吗？**
   - 单机 MinIO 服务存在单点故障，可以通过分布式的方式实现高可用性。
   - 分布式 MinIO 至少需要 4 个节点（4 台服务器）才能发挥其功能，自动引入纠删码功能。
   - 只要有 N/2 个节点在线，MinIO 中存储的数据就是安全的，并且可以进行读取操作。但写入新对象或更新现有对象时，必须至少有 N/2+1 个节点在线。

   > 以一个 8 节点的 MinIO 集群为例：假设有 4 个节点宕机，则剩余的 4 个节点仍然可以保证数据的可读性。但写入操作必须至少有 5 个节点在线。

### 3.5 视频播放解决方案

#### 介绍一下你采用的视频播放解决方案

YouTube、哔哩哔哩等知名视频网站主要基于 MPEG-DASH（Dynamic Adaptive Streaming over HTTP），但一般也支持 HLS（HTTP Live Streaming），特别是在移动设备和一些特定的场景下。

这里我们以 FFmpeg + HLS 实现视频播放为例，进行介绍。

- **FFmpeg**：一个强大的开源跨平台多媒体框架，支持多种音视频格式和协议，提供丰富的命令行参数和库函数。无论是简单的格式转换，还是复杂的音视频编辑，FFmpeg 都能提供可靠的解决方案。
- **HLS**：由苹果公司开发的一种媒体流协议，用于通过互联网实时传输音视频内容，常用于直播和点播服务。HLS 将音视频文件切割成小的媒体段，每段通常为几秒钟长，并通过 HTTP 协议传输。客户端可以根据网络状况和设备性能动态选择不同质量的媒体段进行播放，从而实现自适应比特率流（ABR）。

我们可以使用 FFmpeg 将大视频文件（.mp4）转换为 HLS 格式，生成 .ts 视频片段和 .m3u8 索引文件：

```bash
ffmpeg -i example.mp4 -codec: copy -start_number 0 -hls_time 10 -hls_list_size 0 -f hls output.m3u8
```

运行上述命令后，FFmpeg 将生成以下文件：

- `output.m3u8`：HLS 播放列表文件，包含对所有媒体段文件的引用。
- `output0.ts, output1.ts, output2.ts, ...`：各个 HLS 媒体段文件，每个文件约 10 秒。

然后，将这些文件存储到 MinIO。在前端使用支持 HLS 的播放器库（例如 Plyr、DPlayer），通过加载 `.m3u8` 索引文件动态播放 `.ts` 视频片段，实现流畅的视频播放，无需等待整个视频文件加载。

> 详细介绍：[基于 FFmpeg、HLS 和 MinIO 简单的视频播放解决方案](https://javaguide.cn/)

#### 还有什么可以优化的地方吗？

FFmpeg 处理 MP4 视频可引入队列实现异步，例如 Redis 5.0 中增加的 Stream 类型。如果对实时性要求不高的话，可以基于定时任务来做，例如 Spring Task、XXL-JOB，先将视频文件上传到 MinIO 后再定时批量处理。

### 3.8 分布式锁

### 3.10 排行榜

#### 热度计算公式

热度计算公式需要将点赞数、学习人数、发布时间等因素结合起来。

**公式 1**：`score = a × 点赞数 + b × 学习人数 + c × 发布时间`

**公式 2**：`热度 = (a × 点赞数 + b × 学习人数) / c × (当前时间 - 发布时间)`

其中 a、b、c 是权重系数，可以通过 A/B 测试或机器学习等方法来动态调整。实际项目中可以引入更多的指标到热度计算公式中，例如完课率、评论数、分享数等。

> 为什么要考虑发布时间呢？这是为了避免发布时间过久的课程/视频影响排名，可以考虑对发布时间进行衰减处理，例如使用时间衰减函数或定期降低旧内容的权重。

#### Redis Sorted Set 结构设计

- **Sorted Set Key**：`course-ranking:{yyyyMMdd}`，例如 `course-ranking:20231027` 表示 2023 年 10 月 27 日的课程排行榜。
- **Sorted Set Member**：课程 ID。
- **Sorted Set Score**：课程热度值，根据点赞数、学习人数、发布时间等因素加权计算得到。

#### 定时更新排行榜流程

要实现定时更新排行榜，可以使用 SpringTask 或 XXL-JOB 来定期计算最新的热度值，并更新到 Redis 中：

1. **定时任务**：定时计算当天、最近 7 天和最近 30 天的排行榜。
   - SpringTask：使用 `@Scheduled` 注解来定时更新排行榜。
   - XXL-JOB/Elastic-Job：如果需要分布式任务调度，则推荐使用。

2. **实时更新（基于 Sorted Set）**：当课程相关指标发生变化时（例如用户点赞、学习课程），使用 `ZINCRBY` 命令实时更新对应日期的 Sorted Set 中课程的 score。

3. **定时更新 Redis 中的排行榜数据**：
   - **当天排行榜**：从数据库获取当天所有课程的相关数据，根据热度公式计算每个课程的热度值。
   - **最近 n 天的排行榜**：使用 `ZUNIONSTORE` 来求 n 个 Sorted Set 的并集。

#### 补充建议

1. **选择合适的更新频率**：根据数据更新速度和实时性需求选择。高频率更新可每小时一次，低频率更新可每天数次。
2. **监控 Redis**：监控 Redis 的 CPU 使用率、内存占用率等性能指标，确保定时任务不会对 Redis 造成过大的压力。
3. **使用批量操作**：使用 Redis pipeline 或 Lua 脚本批量操作数据，减少网络 IO 开销。
