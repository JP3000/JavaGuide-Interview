星球里有不少球友用短链接这个项目，也有球友询问这个项目的优化包装建议。

相比较于校园订餐、黑马头条、商城等烂大街项目，这个项目也还是不错的，也比较好包装。

这里分享一下短链系统的项目介绍模板、优化建议以及相关文章和项目推荐。

👉 项目介绍（提供了两个模板，自己参考着修改即可，不要照搬）：

1. 自研短链接服务，除了支持长链接的管理和分享，还提供了深入的分析和跟踪功能，用户可以灵活地管理和优化其链接，从而实现更好的营销效果和业务成果。
2. 一个可以承载高并发和大数据量存储的短链接管理平台，其核心功能是将长接转化为短链接，并且可以统计和分析短链接的访问情况。

👉 技术栈（以马哥的短链项目为例，后面会分享这个项目的地址）：

SpringBoot + SpringCloudAlibaba + RocketMQ + ShardingSphere + Redis + MySQL + Sentinel

👉 核心职责（短链项目常见描述，优化版本）：

1. 基于 Redis + Sesison 实现用户登录认证，采用 Bcrypt 算法加密保存密码，支持短信验证码登录，权限模型采用 RBAC。
2. 基于 MurmurHash 算法生成短链并解决 Hash 碰撞问题。
3. 通过 Redis 布隆过滤器完成判断短链接是否已存在，数据库查询兜底避免误报。
4. 通过 Redis Stream 实现消息队列，对高并发访问短链接场景下的监控信息存储功能进行削峰。并且，通过 Spring Task 定时处理未确认信息。
5. 设计了基于 Sharding-JDBC 自定义分片算法的短链码分库分表解决方案，实现了无需数据迁移的扩容，并使用加权库表位算法解决了扩容后数据倾斜问题。
6. 为了兼容短链接后管用户分页查看短链接功能，在短链接数据分片的基础上增加路由表完成跳转功能。
7. 基于 Sentinel 对短链接生成、重定向等核心接口实现基于用户 ID 的限流，保障了系统在高流量冲击下的稳定运行。
8. 针对高并发下的短链接修改，使用 Redisson 分布式读写锁确保数据修改和访问的安全。
9. 基于 Swagger 生成接口 API 文档，集成 Knife4j 实现 Swagger 文档增强。

👉 可添加/修改的点（我补充的一些可形成差异化的功能点）：

1. 短链支持有效期设置（类似：<魔众短链接系统 | 测试短网址系统  | 快速搭建-更好的运营>），例如 1 天、一周、一个月、一年、永久，可以基于 Redisson 内置的延时队列或者 RocketMQ 延时消息来做。
2. 根据二八定律，大部分请求集中在最近一周生成的短 URL 上，可以考虑将最近一周生成的短 URL 放入 Redis 缓存中。并且，还可以利用定时任务定期将访问频率比较高的短 URL 存入缓存中。
3. 引入第三方登录，例如 Github、Gitee、微信，具体思路可以参考我在星球的分享：为项目引入第三方登录是一个比较... 。
4. 添加项目部署相关的介绍，可以基于 Docker 部署或者直接使用 Linux 部署。并且，最好是能够上线，然后在简历上放上预览地址，这会加分非常多。
5. 利用 ab、Jmeter 等工具对项目核心接口例如短链生成进行压测，并将数据体现在简历上。
